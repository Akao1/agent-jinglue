# 三省六部·经略｜需求说明书

文档 v0.1 · 2026-11-06 · 评审稿

经略是三省六部·官制的产品化迭代。它把任务分工、审批、验收和巡按接到一个本地可独立运行的程序里。官制继续提供规则与角色契约，经略负责执行和留证，两者各自管理版本。本说明书定义首版建设范围和通过条件，所有用例均待实施验收。

## 1. 谁用，经略解决什么问题

首版面向以 用户 为首个使用者的个人多业务工作流。使用者可能同时办理工作、视频制作、学习和长期讨论事项，手头的执行资源可能只有一个 API、只有一个本机 Agent，也可能有多个。使用者要能在同一个对话里交办、审批、验收和查回成果，不用跨工具反复解释任务。

| 使用者关心的事 | 首版承诺 |
|---|---|
| 我手头只有一个接入方式，能不能开工 | 一个已验证的执行者可以完成其能力和授权覆盖的普通任务，独立复核等门禁按官制另行判断。 |
| 换部门或执行者，任务会不会丢 | 接单、退回和切换沿用同一案卷和县，交付与实际执行身份可回查。 |
| 任务办完之后去哪找 | 版图可看现况，县志保留每次真实验收及归档，旧链接仍可定位原任务。 |
| 程序能不能自行把关 | 程序执行权限、前置、验收和身份门禁。模型可提建议，批准和受控写入由相应入口完成。 |

初稿以单机、单用户、一个授权工作区先走通全程为试点条件。业务分类可跨已授权工作区汇总，首版依赖边限定同一工作区。首个模型 API 供应商、首个本机 Agent、支持的 OS 范围、单任务预算和性能目标由可行性试验确认。P0 是首版放行项，P1 是首版稳定后增强项，P2 是单独评估项。

## 2. 对象与状态约定

| 对象 | 要保留的信息及关系 |
|---|---|
| 官制版本 | 案卷保存创建时所用的规则版本及验收依据。运行时安全政策变更需对后续受控动作生效并留痕。 |
| 工作区 | 数据所属、访问授权和交付位置的权威归属。行省分类与工作区权限分开处理。 |
| 行省、府州、县 | v0.1 评审方案中，行省是业务类别，府与州是同一级的两种名称，承接客户、项目或主题。县对应可独立交接和验收的节点，具有稳定编号。同一客户的多笔业务按事项区分。 |
| 案卷与执行尝试 | 记录任务编号、对话引用、部门、阶段、实际执行者、尝试编号、权限与输出证据。切换或重试增加尝试记录，保留原案卷。 |
| 前置关系 | 保存起点县、后继县及真实放行条件。进入可开拓状态时引用当时满足的前置验收批次。 |
| 验收批次与县志 | 保存任务编号、批次、实际验收时间、决定者、证据、归档时间和原件引用。重开追加事件，县志保留历史。 |

办理状态分为待开工、办理中、待批准、待验收、已验收、失败、暂停和取消。前置就绪与归档独立记录。灰地表示待开工，可显示未接壤或可开拓。攻占中按真实阶段显示。进入领地以对应流程的验收通过为准。熟地表示已经归档的验收批次。程序须区分真无记录、数据未纳管、无访问权限和加载失败。

## 3. 功能需求与验收

### 3.1 安装、接入与任职

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| R-01 | P0 | 经略能本地启动，提供独立的首次配置入口。允许选择工作区、执行者和全局默认。 | 分别在只有一个已验证 API、只有一个已验证本机 Agent 的配置下完成普通任务，形成可回查案卷。第二组无需额外 API Key。 |
| R-02 | P0 | 接入支持的模型 API 和有官方可调用入口的本机 Agent。状态区分已发现、待连接、可用及不可用原因。凭据由接入方式保管，经略记录引用。 | 本机已装但未登录时显示待连接。过期凭据显示需重新授权，验证成功才允许接单。日志和导出中无明文密钥。 |
| R-03 | P0 | 用户可为部门设主用和备用，可临时指定执行者，也可让一个执行者兼任多个部门。 | 新增第二个执行者时，旧的手工任职与默认保持有效。权限及能力满足时，依次采用本次指定、部门主用、已批准的部门备用和全局默认。指定者遇阻后由用户决定是否替换。 |
| R-04 | P1 | 通过合成小样推荐任职，展示质量、可用工具、耗时和已知用量依据。无实测时标为初始建议。允许现有 Agent 协助起草。 | 给两个候选执行者相同小样。推荐理由可回查，按用户确认的表生效。手动任职无需小样。 |

### 3.2 对话、接力和受控操作

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| R-05 | P0 | 从对话创建或关联案卷。程序依据官制匹配部门与工序，在可用性、能力、资料授权和额度均满足后派发。 | 一项任务先后经 API 与本机 Agent 处理，原对话和任务编号一致，界面显示实际执行者、阶段、交接理由和结构化证据。开发任务按其门禁推进，普通事项用对应的轻量验收。 |
| R-06 | P0 | 派发只提供当前阶段获准的资料、目标、授权和必要摘要。跨服务商切换重新校验资料范围。 | 拒绝跨工作区的未授权读取，备选服务商不具资料权限时任务停在原阶段。改派或重试保留可回查日志。 |
| R-07 | P0 | 受控操作受程序门禁约束。无法限制写入范围的外部 Agent 只提交建议或补丁，由经略校验及按权限落盘。 | 申请越权路径、撤回授权、链接逃逸或发送同一批准的重复提交均不产生额外或越权写入。授权与动作、资源范围及验收所需版本绑定。 |
| R-08 | P0 | 任务状态区分可安全重试、人工接手和结果未知。写入超时先核原件、版本与占用。 | 注入写入已执行但响应丢失的情形，经略不自动改派重写。恢复后留存核实结果。同一对象的并发写入按同一批准和操作标识只产生一次有效结果。 |
| R-09 | P0 | 验收取用对应规则版本、实际证据和真实执行身份。同一执行者兼任复核时标记同工具复核。 | 单执行者可走完适用的普通验收。要求独立复核时，即使换角色名也停在待复核，直至有符合要求的真实复核和证据。 |

### 3.3 王朝版图、熟地和国史馆

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| R-10 | P0 | 按评审中的业务分层展示行省、府州和县。从台账或对话关联可核原任务，已有旧案可只读查看，有证据后按权限登记。 | 同一任务经改派、重试、府州改名或项目视图调整仍只有一个县。无法确认的旧资料放待核，未分类的已纳管事项放待归类。 |
| R-11 | P0 | 前置关系决定是否可开工。版图查询、筛选和展开保持只读。 | 拒绝不存在的依赖、自依赖及成环依赖。A 未验收时 B 显示阻塞，A 验收后 B 可开工。与其无关的 C 正常可开工。刷新地图不触发派单、归档或周报。 |
| R-12 | P0 | 默认在实际验收完成 **7 天**后把县并入府州的熟地摘要。用户可修改期限。归档标记与县志同次提交，按任务编号和完成批次去重。 | 使用测试时钟验证默认和自定义期限。中断后重跑和并发维护都只得到同一条归档。已归档前置继续满足依赖。改期限只重算未归档批次。 |
| R-13 | P0 | 允许按真实流程重开县，沿用编号。旧验收批次、县志和历史地址可查。 | 重开使旧验收失效时，尚未开工的后继重新判定。在办后继提示复核，已经完成的后继保留其实际记录。重复验收生成新批次。 |
| R-14 | P0 | 点击地块可查看原因、接手者和下一步，能打开案卷、县志和获准原件。允许配置合法跳转目标和保存目录。 | 按名称或旧链接能找到已归档县，显示并可复制有权查看的当前地址。原件迁移经确认后更新索引，断链时保留历史位置和修正入口。 |
| R-15 | P0 | 国史馆提供各地县志导航。已验证通用方法收录正式国史时，继续沿用官制的翰林提名、御史核档、用户批准及版本绑定。 | 完成并归档的县可在国史馆打开县志，正式国史收录记录须具备对应规则和审批证据。 |

### 3.4 御史周巡按与用户决定

| 编号 | 优先级 | 需求 | 验收条件 |
|---|---|---|---|
| R-16 | P0 | 任务记录与版图归属可按周对照。检查已登记未入图、久未归类、疑似错归，并提出已有省归属或新省建议。 | 在授权合成样本中找出预设漏项并给出原始位置、置信度和理由。无记录或无权访问的范围明示为覆盖缺口。 |
| R-17 | P0 | 御史提交报告，用户批准后再执行补归、改归或开省。可手动开省。已驳回建议在无新证据时保持去重。 | 种子案例中用户分别批准和驳回，只有获准事项发生改变。下一轮能查看处理结果。未授权范围在报告里不披露案卷。 |
| R-18 | P0 | 用户或程序维护入口可发起巡按及到期归档。启动时识别欠跑，按同一规则补跑。 | 关闭执行 Agent 的定时器，手动触发或通过程序维护入口仍能完成验收样本的巡按与归档。重复触发不重复写入。 |

## 4. AI 约束和质量验证

- **输入与输出。** 发给执行者的任务包含任务号、部门、阶段、授权范围、必要资料引用和输出约定。返回结果需包含实际执行身份、结果摘要、证据或补丁、外部动作状态及错误。程序检验结构后再确认业务状态。来自资料或工具输出的文字仅作为任务数据处理。
- **候选选择。** 首个 API 和本机 Agent 依据实际接入测试选择。备用仅在已经批准、能力匹配、额度允许且可安全重试时启用。受限制的供应商不得接收相关资料。连接状态、权限和模型能力应分别判定。
- **评测样本。** 普通任务闭环、API 与本机混合接力、权限越界和内容诱导、超时后外部副作用、同工具复核冒充独立、县志去重、错归误报和授权覆盖缺口均须有可重复样本。结构和门禁测试记录通过数，语义任务核对输出及证据。样本未覆盖的模型和任务类型保留验证缺口。
- **用量与回退。** 每次实际调用记录适配器、模型或 CLI 版本、耗时和可获得的用量。未知用量显示未知。限流、费用上限或超时由用户可控。规则或适配器变更需保留版本和回退信息，真实供应商验收结果与模拟验收分开。

## 5. 非功能要求与放行

| 维度 | 首版验收口径 |
|---|---|
| 权限与隐私 | 工作区权限、明确的资料授权和供应商范围同时约束检索、派发、归档与跳转。外部调用和落盘各有审计依据。越权路径和超范围披露的阻断用例全部通过。 |
| 可恢复与可回查 | 重启可从同一案卷继续。操作未知、重复提交、归档中断、原件失效可区分并显示下一步。县志和原件索引支持有权限的检索。 |
| 可用性 | 工作台能找到当前阶段、责任执行者、阻塞原因和审批入口。版图配可搜索列表，颜色辅以文字或图标，核心操作支持键盘。 |
| 运行观察 | 记录首连、派发、归档和地图打开耗时及失败原因。首轮报告说明数据量、设备与接入方式，形成后续性能和成本目标的基线。 |

放行按三道门执行。

1. **隔离验证。** 用合成事项跑完全部 P0 条款。权限、验收与避免重复副作用的固定用例全部通过。用可控时钟验证七天边界，记录每条用例的版本、证据和失败处理。
2. **真实接入验证。** 在授权的本地环境分别用一个真实 API 和一个真实本机 Agent 跑通单端任务，再在同一案卷实际接力。校验实际执行身份、授权资料和证据。覆盖主用故障、结果未知和无合格独立复核时的阻断。
3. **小范围使用验收。** 用户 用一组有真实前置的县完成交办、验收、熟地归档、查回和重开，再执行一次御史巡按并批准或驳回一条建议。通过条件是三类证据齐备，发布前阻断项清零，且能够在当前版本重放必需用例。

P1 可追加任职小样、批量纳管历史候选和更多接入适配。P2 单独评估跨工作区依赖、多用户协作和大规模业务聚合。接入品牌范围、费用、时延和跨平台可用性以实测记录确认。首版仍处设计阶段，接入和产品放行均待实施。
