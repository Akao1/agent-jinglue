# 三省六部·经略｜产品设计

**文档 v0.1 · 2026-11-06 · 设计待评审**

## 1. 产品定位

**经略是官制的产品化迭代。** 三省六部·官制提供角色、职责、阶段、授权和证据规则。三省六部·经略将这些规则落实到独立运行的本地软件，让用户在一个对话里交办任务、调度执行者、验收成果，再从王朝版图找回案卷。官制规则版本与经略程序版本分别管理，任务案卷记录实际采用的版本。

首批使用者定位为同时做视频、工作、学习或持续讨论的个人，以及已经使用模型 API 或本机 Agent 的用户。用户打开产品时主要想确认三件事。什么能开工，正在办的事卡在哪，做完的成果去哪找。以这三项任务判断界面是否需要保留某个入口、标签或说明。

首版以本地个人使用为目标。产品能通过一条受支持的模型 API，或一个已验证能走官方调用入口的本机 Agent，办理其能力和授权覆盖的普通任务。多种执行者可以逐步接入。对需要独立复核的任务，单一执行者只能推进到复核门禁前。

## 2. 核心使用路径

| 场景 | 用户怎么做 | 经略反馈 |
|---|---|---|
| 第一次启动 | 选择工作区，接一个模型 API，或选择本机发现的 Agent 并按提示验证 | 分开显示「已安装」「待登录」「可执行」与失败原因。显示当前可办理的任务，允许稍后增配部门。 |
| 一句话交办 | 在办事对话里说明目标。确认或调整建议的府州、县、前置和验收条件，也可关联原案卷 | 建立稳定任务编号。以简短任务卡显示预期产出、下一步和所需确认。纯咨询可以继续对话。 |
| 接力办理 | 查看任务卡，必要时指定执行者。看到审批或缺件提示时直接打开原案卷处理 | 显示当前部门、真实接手者、接手依据和实际阻塞。切换 API 或 Agent 后，任务编号、对话和证据仍连续。 |
| 验收与回查 | 检查成果与证据，处理必批动作。稍后通过版图、搜索或县志打开原交付 | 验收通过后点亮对应地块并计保留期。到期合并为熟地，原链接和历史仍可查。 |
| 每周巡按 | 查看有依据的漏归类、错归类和开省候选，选择采纳、驳回或暂缓 | 同条建议保留来源、建议理由和决策记录。需要实际调整时交给获授权的流程，下一轮可查看处置结果。 |

## 3. 页面与主要动作

| 页面 | 第一屏需要看到 | 主操作 |
|---|---|---|
| 办事 | 对话、当前任务卡、验收状态和待处理动作。未有案卷时显示「交办任务」 | 交办、关联原任务、确认安排、跳转到待办动作 |
| 王朝版图 | 业务分类、在办与受阻数量、近期领地、已折叠的熟地 | 选择省或府州、选中地块、切换到任务列表、搜索成果 |
| 国史馆 | 「地方县志」和「正式国史」两个清晰入口 | 按府州或节点搜索、打开出处、查验收与归档批次 |
| 御史巡按 | 本次扫描覆盖范围、有证据的发现、待确认和处置情况 | 打开证据、采纳建议、驳回或暂缓 |
| 设置 | 执行者、部门任职、工作区、路径与归档期 | 添加并验证执行者、设置主用与备用、调整保存位置和保留天数 |

首次接入采用逐步展开。默认只有一个执行者时，选好全局默认即可开始普通任务。用户接入第二个执行者后，可以打开任职表为某个部门指定主用或备用。已有 Agent 可以协助填写草案，确认操作留在经略里。

执行安排遵循已获授权的配置。优先采用本次指定，其次为部门主用、已批准的部门备用、全局默认；候选须满足能力、资料权限与可用性。推荐附可验证的小样结果或说明尚无实测。用户明确指定的执行者失败时，页面提示原因并让用户选择替换。结果未知的写入先核实际文件与版本，页面保持原任务等待状态。

## 4. 王朝版图

### 业务分类与地块

本版采用以下展示方案作为设计假设，待原型验证。工作区继续管理权限和案卷存储，业务分类用于导航。不同工作区的可见信息可按授权归到同一业务视图。

| 地图层级 | 对应对象 | 示例 |
|---|---|---|
| 行省 | 稳定业务分类 | 视频制作、工作、学习 |
| 府或州 | 可持续回查的具体事项或对象。两种称呼同级 | 一条视频、一个客户、一项课程或长期主题 |
| 县 | 可单独交接、具有完成条件的办理节点 | 脚本验收、交付核对、复现实验 |

县即地块，任务从登记起有稳定编号。改稿、转交、重开沿用原县，细节在案卷里保留。工作区未纳管、无权限或读取失败各自显示原因；确实没有事项时显示空态。旧材料证据不足时可以进入待核列表，等核清后再关联。持续的新业务可手动开省，也可接受 Agent 或御史的有据建议。临时学剪辑可留在该视频，系统学习剪辑可进入学习省。

### 状态怎样读

| 版图展示 | 真实状态 | 地块侧栏 |
|---|---|---|
| 灰地 · 未接壤 | 有登记的前置未满足 | 展示可见的阻塞任务，链接到原案卷 |
| 灰地 · 可开拓 | 尚未开工，前置均已满足或无前置 | 展示可以开始的下一步 |
| 攻占中 | 已接手或在办 | 展示办理、待审批、待验收或阻塞，并列真实接手者 |
| 已纳入领地 | 已按该业务流程验收，在活跃保留期内 | 展示验收时间、证据和成果入口 |
| 熟地 · 已归档 | 达到完成后的配置期限 | 按府州合并显示，展开可定位原县与地方县志 |

地块的相邻关系服务于导航，是否可以开工由真实前置决定。默认只画选中地块相关的前置线。颜色配文字或图标，地图和列表共用数据与筛选。侧栏只放一个最相关的下一步动作，其余资料在案卷里。

```text
王朝版图           [搜索] [仅看待处理] [切换列表]

视频制作省  ›  样片府
  脚本县    已纳入领地  ─────  分镜县    可开拓
  成片县    未接壤
  熟地 2 项 [展开]

选中 分镜县
  当前 可开拓 · 前置 脚本验收已通过
  接手 待接手                 [打开任务]
```

以上为交互草图。默认布局应让用户直接看出下一步；图例按需展开，避免每块地重复说明。任务列表保留同等的查找、状态和进入能力。

### 成果、归档与历史

默认从实际验收完成时起保留独立地块 **7 天**。可调整保留天数。到期时合并到府州熟地并写一条县志，地块编号、已满足的前置、原成果路径与验收依据继续有效。重开恢复活跃地块并保留既往批次。已完成或失败的历史结果按实际情况展示。

默认打开案卷，用户可按授权设置显示名、成果跳转目标和保存目录，也可复制当前地址。位置失效时展示已知路径，并给有权限的用户修正入口。县志导航按行省、府州进入本区记录，正式国史继续走翰林提名、御史核档和用户朱批。

## 5. 御史巡按如何进入日常

沿现有周五巡按节拍，拟在经略增加「归类漏项」。先比对授权范围内的任务台账和版图，找出已登记未入图、长期未归类及可能错归的事项，再按证据提出归到现有省或新开省的建议。每条发现显示依据、建议归属、置信度和覆盖缺口。建议状态可由待确认进入采纳、驳回或暂缓。采纳后由获授权的流程执行，御史负责核查处理结果。同一条已驳回的建议只有在出现新依据后才再提示。

## 6. 首版体验验收

1. 在一个授权工作区内，只配置一个受支持的执行入口，交办一个有明确验收条件的普通任务。看到完整案卷、真实执行身份和结果。
2. 在同一案卷里交接两个已验证执行者。核对部门、切换理由、已有交付和任务编号。强制独立的环节缺合格复核者时保留待复核。
3. 在一省一府州内创建两个有依赖的县。前置待验收时，后继仍灰。通过验收后点亮后继开工入口，再完成一次熟地归档与回查。
4. 模拟维护重试和任务重开。确认熟地只记录一次，同一个县重回活跃，原完成与归档历史仍能查看。
5. 构造一条可查但未入图的业务和一条无访问权的资料。巡按只把有据事项送入待确认，明确展示范围缺口，用户未确认时分类未发生变化。

首版验证重点是单执行者起步、任务接力、真实依赖与可回查成果。地图的视觉细化、更多适配器与自动推荐质量随真实试点再验证。
